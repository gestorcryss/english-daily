# F1.1: teste das fontes de dicionário

> Data: 2026-10-04. Script: `scripts/f1-1-dictionary-sources-test.mjs`. Resultados em bruto: `scripts/data/raw/f1-1-results.json` (fora do Git).

## Decisão

A fonte principal das palavras passa a ser o **Wiktionary, através dos dados extraídos pelo projecto wiktextract (kaikki.org)**. A Free Dictionary API deixa de fazer parte do plano.

## Como foi testado

Amostra fixa de 204 palavras, 34 por nível (A1 a C2), tiradas das listas CEFR-J e Octanove com semente fixa. Só palavras simples, sem variantes nem expressões. Para cada palavra pediu-se a ficha às duas fontes.

## Resultados

| Medida | Free Dictionary API | Wiktionary (wiktextract) |
|---|---|---|
| Palavras encontradas | 0 de 60 | 203 de 204 |
| Com pronúncia (IPA) | — | 90% |
| Com áudio | — | 92% |
| Com pelo menos 1 exemplo | — | 97% |
| Com exemplo curto, escrito para o dicionário | — | 72% |
| Com sinónimos | — | 78% |
| Tempo de resposta (mediana) | sem resposta em 8 s | 283 ms |

A Free Dictionary API não respondeu a nenhum dos 60 pedidos dentro de 8 segundos. Em pedidos soltos com espera de 20 segundos devolveu o erro 522 (o servidor de origem não responde) em 3 de 5 palavras, e noutra corrida falhou 12 de 12. É um serviço gratuito mantido por uma pessoa, sem garantia de disponibilidade, e no dia do teste esteve em baixo.

## O que o Wiktionary dá a mais

Os dados do wiktextract trazem as traduções que os editores do Wiktionary escreveram para cada palavra. Na amostra:

| Língua | Palavras com tradução |
|---|---|
| Espanhol | 91% |
| Francês | 89% |
| Português | 84% |
| Árabe | 65% |
| Suaíli | 29% |

A cobertura em português desce com o nível: 100% em A1, 94% em A2 e B1, 76% em B2, 79% em C1 e 59% em C2. Os exemplos curtos seguem o mesmo padrão, de 91% em A1 a 47% em C2.

Isto muda o plano de traduções: a maior parte das traduções da palavra vem do próprio Wiktionary, sem custo nem chave. A API de tradução (Azure) fica só para preencher as faltas, que se concentram nos níveis C1 e C2.

## Consequências para o plano

1. O catálogo é construído por nós com scripts: lista CEFR, mais ficha do Wiktionary por palavra, e carregado no Supabase. A app lê do Supabase e nunca fala com uma API de dicionário de terceiros.
2. A função `enrich-word` (ir buscar a ficha a pedido) deixa de ser precisa para as palavras do catálogo.
3. Os exemplos que são citações longas de livros e jornais ficam de fora. Usam-se os exemplos curtos do Wiktionary e, onde faltarem, frases do Tatoeba.
4. Para palavras fora do catálogo (pesquisa no dicionário, fase F4), a decisão fica para essa fase. A candidata é a API pública do próprio Wiktionary.

## Limites do teste

A falha da Free Dictionary API foi medida num só dia. Não prova que o serviço esteja sempre em baixo, mas uma app publicada não pode depender de uma fonte que falha desta maneira sem aviso.
